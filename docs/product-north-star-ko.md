# K-Guard MCP 제품 북극성

## 한 문장

**만드는 흐름은 끊지 않고, 출하는 대충 넘기지 않는다.**

K-Guard MCP는 바이브코더가 만든 결과물을 출하하기 전에 사이트, API, 데이터, 운영 위험을 함께 확인하고, 지금 고칠 것과 다음 행동을 한국어로 알려주는 로컬 우선 감사관이다.

## 제품 인격

- 제품명: `K-Guard MCP`
- 안내 인격: `안경선배`
- 역할: `바이브코딩 선배`
- 태도: 만들었다는 사실을 존중하고, 모르는 것을 탓하지 않으며, 출하 기준만은 흐리지 않는다.
- 말투: 짧고 구체적인 한국어. 위험을 겁주기보다 왜 막혔고 무엇을 고치면 되는지 말한다.

`안경선배`은 별도 엔진이나 또 하나의 게이트가 아니다. `check_my_app`으로 전체 감사를 시작하고 `continue_review`로 끝까지 따라간 뒤, `start_review_before_ship`이 실행하는 Guardian high 판정을 사람이 이해하기 쉽게 전달하는 제품 보이스다.

## 목표 사용자

1. AI로 첫 웹앱을 만든 비전공자
2. Next.js, Express, Supabase, Firebase로 빠르게 MVP를 만드는 1인 개발자
3. 여러 바이브코딩 결과물을 검수해야 하는 소규모 팀 리드
4. 한국 개인정보와 API 노출이 걱정되지만 전문 감사 인력이 없는 팀

## 목표 경험

처음 설치한 사용자가 5분 안에 자기 프로젝트의 `application_assurance`와 출하 상태를 함께 받아야 한다.

- `ship`: 설정한 기준에서는 출하 가능
- `hold_fix`: 막는 항목을 고친 뒤 다시 검수
- `hold_coverage`: 검수 범위나 증거가 부족하므로 출하 보류
- `hold_authority`: 단일 앱 범위나 운영자 서명 증거가 부족하므로 출하 보류
- `hold_qualification`: 앱 위험 판정과 별개로 감사 도구 버전의 검증 증거가 부족하므로 출하 보류

`clear_in_reviewed_scope`는 앱 범위의 critical/high 위험이 해소됐다는 뜻이고 `ship`과 같지 않다. `auditor_qualification`과 canonical authority까지 통과해야만 `ship`을 사용한다.

판정에는 반드시 다음 행동이 최대 3개 붙는다. 사용자는 규칙 목록을 해석하는 데 시간을 쓰지 않고, 첫 수정으로 바로 이동할 수 있어야 한다.

## 핵심 원칙

1. **출하 권한 엔진은 하나다.** 사용자는 `start_review_before_ship`으로 장기 감사를 시작하고, 완료 결과는 내부 Guardian high 하나가 판정한다.
2. **설치한 프로젝트를 바꾸지 않는다.** private workspace binding 밖의 경로는 검사 전에 거부한다.
3. **검수 후 바뀐 코드를 건너뛰지 않는다.** `start_review_before_ship`은 현재 source snapshot과 일치하는 완료된 `check_my_app` 영수증을 요구한다.
4. **문제가 없는 것과 보지 못한 것을 구분한다.** 검수 범위가 부족하면 통과시키지 않는다.
5. **한국 사용자의 실제 데이터를 본다.** 주민등록번호, CI/DI, 계좌, 의료정보, 보존·파기, 접근기록 맥락을 다룬다.
6. **원문을 결과로 되돌려주지 않는다.** 경로, 규칙, 분류, 해시와 필요한 위치만 남긴다.
7. **창작 흐름과 출하 책임을 분리한다.** `check_my_app`은 빠르게 접수하되 전체 범위를 끝까지 보고, 출하 직전에는 fail-closed Guardian을 끝까지 완료한다.
8. **과장하지 않는다.** 인간의 사업 판단, 법률 판단, 무결점 보증, 완전한 타입·프레임워크 이해를 주장하지 않는다.

## 북극성 지표

- 첫 유효 판정까지 걸리는 시간: 5분 이내
- 판정 이해율: 사용자가 추가 설명 없이 `출하/수정/범위 부족`을 구분
- 행동 가능성: 모든 보류 판정에 구체적인 다음 행동 1개 이상
- 출하 무결성: 커버리지 오류, 검사 중 소스 변경, 제어 오류는 통과시키지 않음
- 근거 품질: high/critical 후보는 raw-free fingerprint와 재현 가능한 증거를 가짐
- 현장 성능 주장: 12~20개 owned/partner 앱의 TP/FP/FN 수동 라벨이 준비되기 전에는 강화하지 않음

## 시각 언어

- 기본 인상: 늦은 밤 옆자리 개발 선배의 작업대, 터미널, 체크 셔츠
- 주조색: 먹색 터미널, 형광 녹색 상태, 자홍색 보조 신호, 체크 셔츠를 연상시키는 붉은 강조선
- 형태: 8px 이하 모서리, 촘촘한 정보, 명확한 상태선, 큰 장식보다 실제 결과 우선
- 금지: 공포 마케팅, 과도한 해커 이미지, 의미 없는 네온 장식, 결과보다 큰 캐릭터, 읽기 어려운 생성형 이미지 텍스트

제공된 이미지는 무드보드로만 사용하고 배포 자산에서는 제외했다. 실제 화면은 프로젝트용 원본 이미지를 새로 생성했으며 hash와 생성 경계는 [브랜드 자산 문서](brand-assets.md)에 기록한다.

## 완료의 정의

제품이 이 북극성에 맞으려면 다음이 동시에 성립해야 한다.

- MCP 설치와 첫 스캔이 문서 그대로 재현된다.
- Guardian 결과가 한 줄 판정과 다음 행동을 제공한다.
- 사이트, API, 데이터, 운영 네 영역 중 빠진 영역이 있으면 게이트가 닫힌다.
- 전체 테스트, 한국 코퍼스, 500회 내부 제품 게이트, 라이선스·릴리스 위생 검사가 통과한다.
- 실제 파트너 라벨이 없으면 제품 성능을 인간 시니어와 동급이라고 표현하지 않는다.
